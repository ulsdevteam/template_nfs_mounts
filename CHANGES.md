# Changes in this release

**Scripts**
- `nfs_mount_stat.sh`: rewritten. `retrans_total` was always 0 (indented lines never matched) and measured transmissions, not
  retransmissions; `fsstat` now handles v3 `FSSTAT` and v4 `STATFS`; mount points are matched as plain strings, not regexes;
  large counters print as integers; one `grep` + one `awk` per call instead of ~10 processes.
- `nfs_discovery.sh`: rewritten. Reads `/proc/self/mounts`, no longer emits invalid JSON for duplicate mount points, handles
  IPv6 servers, escapes quotes and backslashes, and de-duplicates.

**Agent config**
- `nfs.mount.check` uses `timeout -k 1 4 stat -t` (was `timeout 5 ls`, heavier and longer than the default agent Timeout).
- `nfs.server.check` is `timeout 4 /usr/sbin/rpcinfo ... && echo 1 || echo 0`: **1 = OK** (was the raw exit code, 0 = OK) and takes
  `{#SERVER},{#MOUNTPOINT}` so two mounts on one server no longer collide on the item key.

**Templates**
- 6.0 and 7.0 were the same file apart from the version tag, with invalid UUIDs, legacy 5.0 elements, numeric enums and
  `change(0,...)` calls. All three versions are now generated by `tools/build_templates.py` in their proper formats.
- Rates use *Change per second* (was *Simple change*), stored as float with units.
- Triggers: 7 instead of 20. Workload ">100/sec" triggers removed; accessibility and server checks require two consecutive
  failures; free-space tiers (5/10/20 %) with dependencies; alerts depend on accessibility; thresholds are template macros.
- The "Low free space" trigger in the old README used the server-check expression; fixed.
- "NFS Data Transfer" graph now plots bytes, not operation counts.
- Dropped item prototypes that do not exist on NFSv4 (`mkdir`, `rmdir`, `mknod`, `readdirplus`) and low-value ones.

**Upgrade note:** `nfs.server.check` changed meaning (1 = OK). Update `userparameter_nfs.conf` and the template together.
